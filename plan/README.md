# 12 周学习计划

目标：建立推理、KV 缓存、存储与后训练衔接的系统理解，读通关键源码，完成一个有数据支撑的小型优化项目。

## 时间与排期

- 基准日期：2026-10-07，周三，Asia/Shanghai。
- 连续 84 天：2026-10-07 至 2026-12-29（首尾计入），预算 192 小时。
- 周一至周五每天 2 小时；周六、周日各 3 小时。按星期安排，节假日不自动调整。
- 启动周 10-07 至 10-11 为 12 小时；之后 11 个完整周为 176 小时；12-28 和 12-29 为 4 小时补漏复验。合计 192 小时。
- 下文 W01–W12 是学习模块与周验收编号。周三启动压缩了 W01 的日历安排，原始七项任务仍须覆盖。
- 未通过验收先补基础并顺延依赖任务；192 小时是预算，日期是基线，不能以赶进度替代验收。调整写入 PROGRESS.md 的变更记录。

## 每周日程与验收

### 第 1 周：Attention 与 KVCache 基础

基线日期：2026-10-07 至 2026-10-11。

- 周一：Transformer 推理路径，标出每一步张量形状
- 周二：推导 Q/K/V、因果掩码和注意力计算
- 周三：手算 prefill 与逐 token decode，解释为什么缓存 K/V
- 周四：比较 MHA、GQA、MQA，推导 KV 显存公式
- 周五：计算不同上下文、并发、精度下的 KV 容量
- 周六：用 CPU/PyTorch 写带缓存与不带缓存的最小 Attention，对照输出
- 周日：画完整请求生命周期，讲清计算量、显存和数据搬运量

主要产物：Attention 验证包：形状图、手算、缓存前后正确性对照和边界说明。

验收：能解释 KV 节省了什么、没有节省什么，以及何时不能复用。

### 第 2 周：推理性能分析

基线日期：2026-10-12 至 2026-10-18。

- 周一：区分 prefill 和 decode 的计算特征
- 周二：学习算术强度与 Roofline，估算性能上界
- 周三：理解 batching、并发与排队
- 周四：定义 TTFT、TPOT、ITL、吞吐与尾延迟
- 周五：设计控制变量和冷/热缓存测试
- 周六：写 KV 容量与搬运时间估算脚本
- 周日：输出一份实验协议，列清指标与可能的误判

主要产物：实验协议（附容量与搬运成本估算脚本）。

验收：看到吞吐提高时，能追问延迟、负载与资源成本。

### 第 3 周：vLLM 请求生命周期

基线日期：2026-10-19 至 2026-10-25。

教材入口：[第三周图文讲义](../lessons/week03/README.md)与[离线交互版](../lessons/week03/index.html)。[资料阅读导航](../sources/w03-reading-route.md)衔接两份教程与本地 V1 实现；本地完整源码快照已保存，开课时先核验版本。

- 周一：固定源码版本，识别 API、Engine Core、Worker
- 周二：追踪请求入队与状态变化
- 周三：追踪 scheduler 如何组 batch
- 周四：追踪模型执行与结果返回
- 周五：追踪 KV 分配、释放和异常路径
- 周六：整理一条完整源码调用链
- 周日：用一个三请求案例手动模拟执行

主要产物：带版本、路径、符号和行号的请求生命周期图。

验收：能指出一次请求各阶段对应的核心类和函数。

### 第 4 周：vLLM 调度与块管理

## 执行规则

1. 原理、手算、源码、CPU 模拟现在就能做。GPU 性能实验等主机就绪后补做；模拟结果不能冒充 GPU 实测。
2. 每周只要求一个主要产物，可以包含代码、数据与说明；未通过验收先补基础。
3. 每次结束发送“做了什么、产物、卡在哪里”，再附实际时长与验收回答，下一次据此调整。
4. 说“开始今天的学习”时，根据进度而非只看日期提供当天完整讲解、练习与验收题。没有完成记录时从 W01 第一次任务开始。
5. 读源码记录版本或快照指纹、文件路径、符号及行号。先确认本地实现，不能把其他版本的设计直接套用。
6. 有 .codegraph/ 的源码库，理解或定位代码先调用 CodeGraph；没有索引则跳过，不自动建索引。
7. 后训练框架、GPU 型号和远程仓库目前均未指定，留待对应阶段确认，不虚构环境或接口。
