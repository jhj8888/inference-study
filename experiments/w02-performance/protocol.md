协议版本：1。性质：教学示例与待执行的真实实验设计。助手已生成模拟数据；学习者尚未填写或验收。

## A. 本周现在就能完成的方案

### 问题与可证伪假设

在固定上下文、参数规模、精度和硬件假设下，增加活动 decode batch 是否提高总吞吐？这种变化是否同时提高单请求 token 速率？

预先指定主指标：模型估计的总输出 token/s。约束指标：单步间隔、单请求 token/s、逻辑 KV 容量。假设：B 从 1 增至 8、32 时总吞吐上升，但单步间隔与 KV 容量也上升。这里研究的是模型关系，不推断真实引擎收益。

### 固定条件与比较矩阵

| 条件 | 固定值 |
| --- | --- |
| 模型假设 | 7×10^9 稠密计算参数、14 GB 权重；L32/Hq32/Hkv8/d128 |
| KV | 每元素 2 byte、无前缀共享 |
| 硬件假设 | 200 TFLOP/s、1500 GB/s；每步额外 1 ms |
| 主比较 | S=8192，B=1 / 8 / 32；每请求每步一个 token |
| 敏感性 | 固定 B 后扫描 S=1024 / 8192 / 32768 |
| 排除项 | 没有真实调度、排队、通信、分配器、内存容量上限或质量评估 |
| 证据类型 | 理论估算，不能表述为某款 GPU 的 benchmark |

### 补充计算与核验

1. 手算 1 GiB/25 GB/s，再加入每 4 MiB 一次 40 μs 的串行开销。
2. 用构造 trace 分别算 A 的 TPOT 与最大 ITL、B/C 的两种平均方式。
3. 重建 30 轮 M/M/1 模拟，保留全部轮次，不按接近解析值的程度筛选。
4. 使用 test_models.py 与 JS/Python 对照检查，验证单位、边界、失败和单 token 语义。

### 数据与统计约定

默认脚本和运行命令见 [README](README.md)。代码指纹与环境由 data/metadata.json 记录，图表脚本位于 ../../lessons/week02/build.py。

构造服务指标窗口为 0–500 ms，所有请求计划开始和结束均在窗内；失败计入 offered/failed，不计入成功 token 分子；每请求 TPOT 等权，汇集 ITL 每间隔等权。单 token TPOT/ITL 不适用，本例 SLO 按 TTFT 判断。分位数为 nearest rank。

模拟每个利用率使用五个预定种子、各 2000 个启动过渡请求和 10000 个观测请求。报告每轮 mean/p50/p95/p99 与五轮范围，范围不是置信区间。启动过渡长度与观察时长在近饱和区需要敏感性检查。

### 工作负载

固定一个 token 化后的请求 trace，保存哈希。预先说明输入/输出长度分布、采样/EOS、共享前缀比例、请求数及长度分层。输出上限与实际长度均记录。

选择开环或闭环并解释原因。开环保存计划到达时间及实际发送时间，记录限流/客户端排队；闭环记录并发数与 think time，不把闭环吞吐当作任意到达率下的稳定能力。

负载扫描的具体到达率或并发值：待填。每个点固定除受控变量之外的条件；记录实际活动 batch 与 token budget 使用，不能只看配置上限。

### 缓存条件

| 实验组 | 预热与状态 | 必须留存的证据 |
| --- | --- | --- |
| 热引擎 + 冷前缀 | 稳态初始化已完成；前缀复用关闭或按固定版本重置，检查同轮共享 | 命中 token/块、实际 prefill 工作量、重置/禁用方式 |
| 热引擎 + 热前缀 | 固定预热 trace、prefix token ID 和命中长度 | 命中率、保存位置、淘汰/取回字节、额外数据路径 |
| 进程冷启动（另测） | 单独记录加载、编译、图捕获 | 启动时间线；不与上两组稳态混算 |

如接入 CPU/SSD/远端 KV，增加每层状态与取回字节证据。不要把 OS page cache 命中算成 SSD 实际读取，也不要将引擎本身命中算成外部缓存的收益。

### 计时和样本

- 指标边界：scheduled / send / server admission / first output / 每次输出 / last output / done，注明哪些可直接观测，哪些需要服务端 trace。端点的空输出与多 token 流块处理写明。
- 默认有限 cohort 协议：从首个计划到达至最后完成/失败/超时，包含排空。若改成稳态窗，必须重写跨窗请求、部分输出和未完成请求的分子/分母规则。
- 正式 A/B 配对重复 5 轮，预先生成顺序；预热请求不进入正式指标。先做小规模正确性试跑，正式请求数和每轮时长在看 A/B 结果前锁定：待填。
- 独立轮次报告 p50/p95/p99、均值、样本数。若尾部样本不足，增加所有组的运行规模并记录修订，不仅追加对某组有利的轮次。
- 失败、超时、取消、拒绝与重试分列；未完成数量和客户端迟发也报告。不能只保留完成请求后声称整个系统无延迟退化。
- SLO 预先填写：TTFT≤___、TPOT≤___、max ITL 或 p95 ITL≤___；声明逐请求还是总体分位数约束、单 token 处理与 goodput 计算规则。
